## Method

Navigation and selection used ADB-injected D-pad/Back keys on the physical TV.
Fresh native hierarchies verify selected controls while reduced motion permits
the UI to settle. Animated live previews can prevent UIAutomator from reaching
idle; capture 110 is screenshot-only and is not used as hierarchy/focus proof.
Raw screenshots and native view dumps verify full-screen ambient entry; the
native AmbientWakeView must be mounted before the measurement helper proceeds.

Each phase captures two 1920×1080 images, waiting eight seconds after the first
capture completes. Actual start/end times are recorded. The helper settles for
two seconds before the first image. There is no UIAutomator, input or screen
mirroring during each pair. Readback can perturb rendering, so these samples do
not measure smoothness, latency or exact animation timing.

Clock/date/details can change while ambient is active. Pixel comparisons
therefore use only three backdrop regions outside all four information slots:
top `(100,20)-(1820,100)`, bottom `(100,980)-(1820,1060)` and the central gap
`(950,100)-(970,980)`. Raw RGB equality, mean absolute RGB difference and changed
pixel fraction are recorded. This is a sampled-background check, not proof of
continuous stillness or a test of information rotation.

the OS value, without restarting HomeScreen. The native ambient wake view was
present and focused during all four phases.

Focused-card motion, sampled plasma stillness under both reduced-motion paths,
and live OS stop/resume behavior passed for this Sony/build. No application source
change, APK rebuild or backend deployment was needed. The private evidence
verifier checks selected preferences, matching ambient options, system-value
restoration, all four pixel-comparison outcomes, retained PID and final dashboard
focus. Product unit tests were not rerun because product source was unchanged;
documentation diff/link checks passed.
